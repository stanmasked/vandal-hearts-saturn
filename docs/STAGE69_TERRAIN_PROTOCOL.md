# Stage69 — C++/Python terrain protocol round-trip

Stage68 had separate Python serialization and C++ parser tests. Stage69
closes the gap by **actually invoking the compiled C++ parser with output
generated by the Python exporter** in an independent GitHub Actions step.

The entire test uses invented 2x2 numerical terrain, invented source labels,
and fabricated observation evidence. It is neither original Saturn map data
nor a gameplay reproduction.

Checks:
- Stage66/67 evidence/coverage validation accepts the fully supported
  synthetic fixture (this **does not** imply authenticity).
- Python exporter emits strictly ordered `VH_TERRAIN_UNVERIFIED_V1` rows.
- Host C++ parses and independently tallies tile counts, blocked/walkable
  flags, movement costs and elevation.
- Changing one cost changes the native aggregate as expected.
- Missing/reordered/extra cells, invalid passability or cost, absurd
  elevation and forged version headers are rejected by the native parser.
- The native `Battle` contains **zero units**; no combat attributes or
  original scripts are inferred.
- The receipt contains only fixed synthetic aggregates; no source paths,
  original graphics, audio, files or human claims.

Run on a host machine:

```bash
cmake -S . -B out -DCMAKE_BUILD_TYPE=Debug
cmake --build out --parallel 2
ctest --test-dir out --output-on-failure
python3 -m tools.check_terrain_bridge --binary out/vh_terrain_probe
```

The private original Saturn image is not required, accessed or copied by
Stage69. Next content milestone remains independent first-battle source
verification under Issue #11.
